# Godot 4 2D Mobile-Friendly Starter Kit Implementation Plan

This plan details the architecture and structure for a production-ready, highly scalable Godot 4 2D starter project optimized for mobile (Android/iOS) and suitable for games ranging from simple puzzle games to 50+ scene platformers.

## Proposed Architecture

To ensure the project scales to 50+ scenes without becoming a tangled mess of spaghetti code, we will enforce strict architectural rules:

1. **Strict Decoupling via `SignalBus`:** Scenes will almost never communicate directly with each other. They will emit signals to a global `SignalBus` autoload, and interested parties will listen.
2. **Composition over Inheritance (Component Pattern):** We will use reusable Nodes (`HealthComponent`, `HitboxComponent`, `HurtboxComponent`, `StateComponent`) instead of deep inheritance trees (`Enemy -> WalkingEnemy -> ShootingEnemy`).
3. **Data-Driven Design:** Configuration and balancing data will be stored in custom Godot `Resource` scripts rather than hardcoded in Nodes.
4. **Asynchronous Scene Loading:** The `SceneLoader` will use Godot 4's `ResourceLoader.load_threaded_*` APIs to prevent freezing during large level transitions.

### Project Structure Overview

```text
res://
├── .godot/                # Generated by Godot
├── project.godot          # Project configuration
├── .gitignore             # Godot specific git ignores
├── README.md              # Project documentation
├── autoload/              # Singletons (GameManager, SceneLoader, etc.)
├── core/                  # Reusable components and event bus
├── scenes/                # Composed scenes (Player, Enemy, Items)
├── levels/                # Game levels (Level1, Level2)
├── ui/                    # User interface scenes (MainMenu, HUD, PauseMenu)
├── scripts/               # Standalone scripts (FSM, utils)
├── resources/             # Typed data resources (SaveData, GameConfig)
├── assets/                # Art, audio, fonts
└── tests/                 # Unit and integration tests
```

### [Autoloads / Singletons]

Singletons that manage global game state and systems.

#### [NEW] `res://autoload/SignalBus.gd`
- Centralized event bus. Defines all global signals (e.g., `signal game_paused`, `signal player_died`, `signal score_updated(new_score)`).

#### [NEW] `res://autoload/GameManager.gd`
- Manages high-level game state (menu, playing, game over). Tracks score, lives, current level.

#### [NEW] `res://autoload/SceneLoader.gd`
- Handles async background loading of scenes and displays a loading screen with a progress bar.

#### [NEW] `res://autoload/AudioManager.gd`
- Manages BGM and SFX. Pools AudioStreamPlayer nodes to prevent audio cutoff when multiple sounds play simultaneously.

#### [NEW] `res://autoload/SaveManager.gd`
- Serializes and deserializes a `SaveData` Resource to user:// directory.

### [Core Components & Systems]

Reusable logic blocks attached to Entities.

#### [NEW] `res://core/components/HealthComponent.gd`
- Tracks health, emits `health_changed` and `died` signals.

#### [NEW] `res://core/components/HitboxComponent.gd` & `res://core/components/HurtboxComponent.gd`
- Standardized areas for dealing and receiving damage.

#### [NEW] `res://core/utils/ObjectPool.gd`
- A reusable node pool for instantiating bullets/effects efficiently to avoid `queue_free()` and `instantiate()` overhead during gameplay.

#### [NEW] `res://core/fsm/StateMachine.gd` & `res://core/fsm/State.gd`
- Base classes for a robust Finite State Machine.

### [UI & Menus]

#### [NEW] `res://ui/MainMenu.tscn` & `.gd`
- Play, Options, Quit. Hooks into `SceneLoader` to transition to the game.

#### [NEW] `res://ui/LoadingScreen.tscn` & `.gd`
- Simple progress bar scene used by `SceneLoader`.

#### [NEW] `res://ui/PauseMenu.tscn` & `.gd`
- Pauses the tree (`process_mode = Node.PROCESS_MODE_WHEN_PAUSED`).

#### [NEW] `res://ui/HUD.tscn` & `.gd`
- Listens to `SignalBus` to update score/health without needing a reference to the Player.

### [Starter Gameplay Demo]

#### [NEW] `res://levels/Level_01.tscn`
- Basic tilemap, instances of Player, Enemies, and Collectibles.

#### [NEW] `res://scenes/entities/player/Player.tscn` & `.gd`
- `CharacterBody2D`. Uses Input Map (touch/kb/joypad). Demonstrates delta-based movement and FSM for states (Idle, Run, Jump).

#### [NEW] `res://scenes/entities/enemy/Enemy.tscn` & `.gd`
- Uses FSM (Patrol, Chase) and Component pattern (Health, Hitbox).

#### [NEW] `res://scenes/interactables/Collectible.tscn` & `.gd`
- Area2D that updates score via `SignalBus` and uses `ObjectPool` or simple `queue_free()` depending on frequency.

### [Resources & Config]

#### [NEW] `res://resources/SaveData.gd`
- Godot Resource script defining variables to be saved (high score, unlocked levels).

### [Dev Tooling & Documentation]

#### [NEW] `res://.gitignore`
- Standard Godot ignores (`.godot/`, `*.translation`, `export_presets.cfg` if containing secrets, etc.)

#### [NEW] `res://tests/SimpleTestRunner.gd`
- A basic script to assert conditions and run through component tests.

#### [NEW] `res://README.md`
- Extensive documentation on how to use the template, add levels, and extend the architecture.
